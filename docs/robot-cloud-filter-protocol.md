# Протокол фильтра облака — 6 ноября 2026

Родитель `6d54bff`, ветка `feat/robot-cloud-filter`. Условия зафиксированы до
первых новых опытов Gazebo этого этапа. Цель — убрать насыщенные дальности из
подтверждений пола и отделить собственную геометрию по точным TF.

## Контракт

- Min/max задаются профилем датчика: `pinned` 0,8/30 м, `l1_near` 0,05/30 м.
  Исключение границ из положительной опоры с прежним допуском 10 мкм.
- STOP использует только валидные дальности для плоскости/подтверждений пола,
  но сохраняет конечные граничные возвраты как возможные препятствия.
  Геометрический self-фильтр не удаляет точки из независимого STOP.
- Карта использует все visual и collision формы из фактического
  `robot_description`. Примитивы проверяются аналитически; mesh — по внешним
  ограничивающим прямоугольным параллелепипедам, полученным нативным
  `gz::common::MeshManager` 5.9.0, с SHA-256 каждого из шести исходных файлов.
  Загрузка учла scene transforms COLLADA; это не пересечение точных треугольников.
- Фиксированный запас к формам **0,02 м**, выбран до опытов. Это консервативная
  гипотеза фильтра, не статистически гарантированный предел шума настоящего L1.
- Нужны точные TF всех звеньев с формами на метку облака. Частичный набор,
  отсутствующая модель, неподдерживаемая форма или другой хеш mesh не дают
  свежую карту. Изменение модели сбрасывает пространственную эпоху.
- Удалённая точка корпуса/границы не даёт свободного пола: её проекция
  запрещает положительную метку в той же клетке и не очищает старое препятствие.
- Старый общий прямоугольник исключения можно заменить только в режиме
  `geometry`; `legacy_body` остаётся явным сравнительным режимом.
- Порог три точки одного скана, конфликт высоты, TTL, габарит 0,7020797 м,
  цель 3 м, скорость 0,05 м/с и критерии движения/карты не смягчаются.
  Фильтр не интерполирует пол, не проверяет тени лучей и не управляет движением.

## Проверки

1. Все старые pytest-проверки плюс примитивы/повороты, mesh scale/origin/hash,
   visual вне collision, насыщенная дальность как запрещённая опора и сохранённое
   препятствие, проекция удалённой точки, отсутствие одного TF и смена модели.
2. Новые неподвижные floor-audit для `pinned` и `l1_near`: первые 15 подходящих
   разных сканов обычного пола и по 15 после удаления пола в проёме 0,6×0,6 м.
   До удаления нужен положительный контроль в будущем проёме, после — ноль
   точек пола и ложных свободных внутренних клеток. Проверить loss/TTL/recovery.
3. Повторить прежние STOP и короткую карту при исходном профиле. Дополнительно
   повторить неподвижный режим `legacy_body` на ближнем профиле для сравнения
   масок; параметры дальности/сцены и обработка исключённых клеток одинаковы.
4. Один прежний двухметровый `--motion-only --audit-motion --headless` на исходном
   профиле: физические пределы, odom, геометрия и ложные свободные клетки сохраняются.

Сохранять все попытки и исходные маски/облака. Эталон Gazebo используется
только наблюдателем. Даже успешные опыты фильтра не подтверждают сплошной
пол под лапами и не открывают планировщик.
