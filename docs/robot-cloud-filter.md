# Фильтр дальности и собственной геометрии

Карта теперь отличает исключённые точки корпуса от измеренного пола под
старым общим прямоугольником. В защищённом запуске выбран `self_filter_mode=geometry`.
Работают прежние `run_local_map.sh`, `run_obstacle_demo.sh` и тестовый скрипт.
Геометрический фильтр не публикует команды.

## Как обрабатывается облако

1. Сохраняются исходные время/координаты. Неконечные и насыщенные min/max
   значения не подтверждают пол; диапазон соответствует выбранному профилю
   датчика, с допуском 10 мкм к границе.
2. Карта читает настоящий `/robot_description` с transient-local QoS. Все
   visual и collision формы входят в фильтр. Для шести mesh проверяются
   SHA-256 установленных файлов, в том числе при `ament --symlink-install`.
3. Для каждого звена с формой требуется TF **на метку облака**. Нет одного
   преобразования — нет нового наблюдения. Последняя поза вместо нужной
   не используется. Новая/повреждённая модель сбрасывает старую пространственную
   эпоху; неподдерживаемая форма или изменённый mesh оставляют карту недействительной.
4. Box/sphere/cylinder проверяются в собственных системах координат с origin/rpy.
   Mesh используется как внешний параллелепипед, полученный загрузчиком Gazebo
   с учётом преобразований COLLADA. Фиксированное расширение всех форм — 2 см.
5. Исключённая точка не позволяет сделать свободной клетку своей проекции
   и не очищает запомненное препятствие. Это важно, когда в одну клетку попали
   и точки пола, и точка корпуса/насыщенной границы.

Старые пороги пола, срок хранения и габарит диагностики сохраняются. Фильтр
не заполняет пропуски и не проверяет тени лучей. Внешний параллелепипед может
включать пустое пространство и исключать часть настоящего пола — это потеря
наблюдений, а не основание уменьшить его до успешной карты.

Независимый STOP применяет диапазон только к **положительным подтверждениям пола**.
Все конечные граничные возвраты сохраняются как возможные препятствия; self-фильтр
карты не удаляет их из STOP. При нехватке валидного пола движение не разрешается.

## Отчёты и сравнение

`mapping/local_map_report.json` и `/guidedog/local_map_status` содержат `cloud_filter`:
режим, числа конечных/насыщенных/собственных/сохранённых точек, SHA-256 модели,
mesh и число звеньев/форм. `mapping/support_report.json` показывает прежнюю
диагностику покрытия; сопоставлять её с основной картой нужно по метке источника
и `snapshot_digest`.

`legacy_body` оставлен как сравнительный режим с прежним прямоугольником.
Новая проверка диапазона и запрет исключённых клеток сохраняются и в нём,
поэтому это не побитовое воспроизведение старого коммита.

Неподвижный опыт с новым фильтром:

```bash
~/guidedog_ws/src/GuideDog-Go2/scripts/test_obstacle_demo.sh \
  --floor-audit --headless --sensor-profile l1_near --self-filter-mode geometry
```

Отдельно сравнить прежний прямоугольник:

```bash
~/guidedog_ws/src/GuideDog-Go2/scripts/test_obstacle_demo.sh \
  --floor-audit --headless --sensor-profile l1_near --self-filter-mode legacy_body
```

Скрипты запускают сцены последовательно, сами завершают принадлежащие им процессы
и требуют новый каталог отчёта. `pinned` остаётся датчиком по умолчанию;
`l1_near` — экспериментальная модель ближней дальности.

При самостоятельном `ros2 run ... local_mapper` режим по умолчанию остаётся
`legacy_body` для совместимости; полный фильтр включается параметром
`-p self_filter_mode:=geometry`. Ему нужны фактическая модель и все её TF.
Согласовать `lidar_min_range`/`lidar_max_range` с источником обязательно.

## Откуда взяты границы mesh

Новый Python-узел не требует компиляции C++ при запуске. Каталог
`guidedog_perception/mesh_bounds.json` с шестью небольшими записями уже включён
в пакет. Инструмент `tools/mesh_bounds/` нужен для независимого повторения
экспорта на Ubuntu, если проверяется/изменяется закреплённая зависимость:

```bash
source /opt/ros/jazzy/setup.bash
cmake -S tools/mesh_bounds -B /tmp/guidedog_mesh_build \
  -DCMAKE_PREFIX_PATH=/opt/ros/jazzy/opt/gz_common_vendor
cmake --build /tmp/guidedog_mesh_build
python3 scripts/generate_mesh_bounds.py \
  --loader /tmp/guidedog_mesh_build/guidedog_mesh_bounds \
  --mesh-dir "$(ros2 pkg prefix unitree_go2_description)/share/unitree_go2_description/meshes" \
  --output /tmp/mesh_bounds.json
```

Изменение хеша mesh требует отдельной проверки модели, а не отключения проверки.
Ни нативный экспорт, ни выбранный запас 2 см не подтверждают калибровку
настоящего Go2/L1. [Протокол](robot-cloud-filter-protocol.md) сохраняет условия
проверки, [отчёт](robot-cloud-filter-validation.md) — фактические результаты
и ограничения для следующего этапа.
